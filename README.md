# 个人时间管理工具

一个面向个人工作的本地时间管理工具。它通过统计每天的工作时间，帮助你理解自己的工作节奏、安排任务，并依据每日和每周的数据持续调整工作方式。

应用由 Go 后端、原生单页前端和 SQLite 本地数据库组成：无需独立数据库服务，数据默认保存在本机。

## 产品目标

将“计划做什么”“实际花了多久”“工作状态如何”放在同一个工具中：

```text
任务管理 → 开始计时 / 补录 → 每日与每周时间分析 → 调整任务与工作安排
```

## 功能模块

### 时间记录

通过两种方式记录每天的工作时间：

- 开始计时：选择任务后开始，结束时自动保存记录；顶部导航栏会显示当前任务、已计时长和结束按钮。
- 补录记录：填写开始、结束时间、关联任务、标签和备注，补录过去或已完成的工作。补录卡片会实时显示时长，并在添加成功后保留日期与任务选择、把开始时间接上本次结束时间，便于连续补录。
- 拖拽补录：在今日页（以及分析页的当日视图）的时间轴空白处横向拖动，可直接圈选一段时间并打开补录弹窗，自动预填起止时间。

补录的时段与已有记录重叠时会被拦截，并列出冲突的记录；确认后仍可保存（例如并行处理多个任务），但需注意重复统计会让工时偏大。同一时刻只允许有一条“进行中”的记录。

时间记录会显示在时间轴中。关联任务时，时间块使用该任务自己的颜色（由任务 ID 决定，同一任务在时间轴、任务列表和分析图表中颜色一致）；未关联任务时回退为标签颜色。

### 任务管理

任务以标签而不是传统分组进行管理，适合一个任务同时属于多个工作维度的场景，例如“项目 A + 紧急 + 开发”。

- 支持任务、子任务、优先级和截止日期；任务状态完全由标签表示。
- 一个任务可拥有多个标签，并可在编辑任务时调整标签顺序。
- 创建子任务时会复制父任务当时的标签；创建完成后父子任务标签彼此独立。
- 每个任务拥有由 ID 决定的固定颜色，用于时间轴、任务列表和分析图表。
- 补录/编辑工时段以“关联任务”为主控项，标签仅用于筛选任务下拉列表（任一标签匹配）。
- 勾选完成会自动添加“已完成”标签；重新打开任务会自动移除该标签。
- “今日任务”是“进行中”标签的任务看板：加入进行中即添加该标签，移出则删除。看板只显示未完成任务，勾选完成的父任务会同时把其子任务移出进行中，已完成任务不再显示在看板中。
- 子任务指任何有父节点的任务；今日看板会保留未完成的子任务以显示层级。
- 标签筛选支持 AND、OR、NOT 组合，应对复杂任务关系。
- 标签可设置是否参与时间分析中的标签分布统计；“进行中”“已完成”等状态标签默认不参与统计。

### 时间分析

时间分析提供两个维度：

- 每日时间分析：查看当天总工时、完成任务、最长专注、与昨日对比、任务/标签占比和时间轴。
- 每周时间分析：查看每日趋势、最高产日、与上周对比、任务/标签占比和每周纵向时间轴。

今日页的记录使用单日 24 小时纵向时间轴，进入页面时会自动将当前时间放在可视区域中央。每日概览会在进入今日页时重新计算，并在停留页面期间定时刷新。

每日与每周分析页均可填写总结，用于记录收获、问题和后续调整计划。

## 页面设计与功能

前端是一个不依赖前端框架的单页应用（SPA）。页面入口统一由 `web/index.html` 提供，`web/app.js` 根据顶部导航切换四个视图：**今日、任务、分析、设置**。应用启动时会先加载标签、任务和当前进行中的计时记录，然后默认进入“今日”页。

### 全局布局

- 顶部栏：左侧是“时间管理”品牌和主导航；右侧显示当前日期、今日工作时长。
- 全局计时器：存在进行中的时间记录时，顶部显示任务名称、实时计时和“结束”按钮；切换页面后计时不会丢失。
- 底部状态栏：显示今日效率、连续专注天数和本周总工时。
- 统一模态框：新建/编辑任务、标签和时间记录都使用同一个居中的编辑弹窗；点击遮罩或关闭按钮可退出。
- 响应式布局：桌面端使用左右分栏和多列分析卡片，窄屏会自动堆叠为单列，并保留时间轴的横向/纵向滚动。

### 今日页

今日页是日常工作的主工作台，布局由“概览 + 操作区 + 时间轴”组成。

#### 今日概览

左侧概览面板展示当天的核心指标：总工时、任务完成数、完成率、与昨日工时差值、最长专注时段和进行中任务数，并用饼图展示标签分布。页面停留期间会定时刷新分析数据，因此正在计时的记录会实时计入总工时。

#### 补录工时

补录卡片用于录入已经完成、过去发生或不方便实时计时的工作：

1. 填写开始日期/时间和结束日期/时间；跨天记录可以使用不同的起止日期。
2. 先按标签筛选任务，再选择具体任务；标签本身只是筛选条件，实际记录优先关联选中的任务。
3. 可填写备注，页面会实时预览时长。
4. 保存成功后会保留日期、标签筛选和任务选择，并把下一条记录的开始时间接到上一条结束时间，适合连续补录。

如果结束时间为空，记录会作为进行中的记录保存；但系统同时只允许一条进行中的记录，因此已有活动计时器时不能再补录另一条未结束记录。

#### 任务看板

任务看板只展示带“进行中”标签且未完成的任务。可以按其他标签继续筛选，也可以直接新建标签或任务。任务行支持：

- 勾选完成/重新打开；完成会添加“已完成”标签，重新打开会移除该标签。
- 通过拖拽调整顶层任务顺序，排序结果会写回任务优先级。
- 点击任务进入任务内嵌分析；任务颜色与时间轴中的时间块一致。

#### 时间轴分析与今日记录

下方左侧是当日纵向时间轴，支持“全天”和“工作时段”两种显示范围。时间块按任务颜色显示，未关联任务时使用标签颜色；点击已有时间块可编辑或删除，拖拽时间轴空白区域可直接圈选时间并打开补录弹窗。

右侧“今日记录”按时间顺序列出当天记录。时间记录编辑时可以重新选择关联任务、查看任务标签和修改备注；遇到与已有记录重叠的时段，页面会列出冲突记录，用户确认后才会以允许重叠的方式保存。

### 任务页

任务页用于维护完整的任务树和标签体系，采用“左侧标签导航 + 右侧任务列表”的设计。

#### 标签导航

左侧列出“全部”和所有标签。每个标签显示自己的颜色，并提供编辑、删除入口。标签编辑可以设置名称、描述、颜色和是否计入分析中的标签分布；“进行中”“已完成”等状态标签默认不计入统计。

#### 任务列表与筛选

右侧以树形结构展示任务和子任务。顶部提供新建任务、状态筛选和排序：

- 状态筛选：全部、进行中、未开始、已完成。
- 排序：按创建时间最新/最早。
- 标签规则：选择多个标签后可使用 OR（命中任一标签）或 AND（同时命中所有标签）。再次点击标签会切换为 NOT 排除条件。
- 如果只有子任务命中标签，仍保留父任务节点，以便理解层级关系。

任务编辑弹窗支持标题、描述、优先级、截止日期、多标签和“加入进行中”。标签顺序可以上下调整，第一个标签作为任务的主标签。创建子任务时会复制父任务当时的标签，之后父子任务标签独立维护；删除父任务会连同子任务一起删除。

#### 任务内嵌分析

点击任务标题会在任务行下方展开分析区域，不离开任务列表即可查看：

- 累计总工时、当前月份工时、时间记录数和子任务数。
- 按月份切换的工时热力图，颜色深浅代表每天的工作量。
- 任务描述和当前月份的时间记录列表。
- 时间记录列表中的记录可以继续编辑或删除，删除记录不会删除任务。

### 分析页

分析页用于回顾历史工作数据，顶部通过分段控件切换“每日”和“每周”，并提供日期/ISO 周选择及上一期、下一期按钮。

#### 每日分析

每日视图先展示所选日期的时间轴，再展示分析卡片：

- 总工时、记录数、完成任务数、进行中任务数。
- 最长连续专注时段及其包含的记录数。
- 与前一天的工时差值和百分比。
- 任务占比和标签占比饼图。
- 当日总结编辑框，保存到对应日期。

每日时间轴和今日页使用相同的交互：可以切换全天/工作时段、点击时间块编辑，也可以在空白处拖拽创建时间记录。选择当天日期时会显示当前时间线。

#### 每周分析

每周视图面向一周级别的节奏判断，包含：

- 本周总工时、记录数、完成任务数。
- 最高产日和该日工时。
- 与上周的工时差值和百分比。
- 7 天工时趋势柱状图。
- 每天一列的纵向周时间轴；支持全天/工作时段切换和时间轴放大/缩小。
- 任务占比、标签占比和本周总结编辑框。

分析中的标签分布只统计启用了“计入标签分布统计”的标签。一个任务有多个统计标签时，单条工时会在这些标签之间均分，避免标签百分比重复累加超过 100%；没有关联任务的工时会归入“未关联任务”。

### 设置页

设置页保持简洁，只负责影响浏览器端显示的偏好：

- 主题：白色或黑色。
- 工作时段时间轴：设置开始小时和结束小时；“工作时段”模式按该范围展示，“全天”模式始终展示 00:00-24:00。

设置值保存在浏览器 `localStorage` 中，不写入 SQLite，因此更换浏览器或清除站点数据后需要重新设置。工作时区由服务端 `TZ` 环境变量决定，前端展示使用浏览器本地时间。

### 页面之间的数据流

```text
标签/任务页维护数据
        ↓
今日页开始计时、补录或编辑记录
        ↓
时间记录写入 SQLite
        ↓
每日/每周分析接口计算统计
        ↓
今日页和分析页展示时间轴、饼图、趋势和总结
```

页面只通过后端 API 读写业务数据；主题和时间轴显示范围是浏览器本地设置。后端启动时会自动创建数据库目录、应用 schema，并尝试将旧版本的分组、任务状态和时间记录字段迁移到当前的标签模型。

## 技术架构与目录

```text
.
├── main.go                 # 程序入口：读取环境变量、打开数据库、嵌入并提供前端
├── internal/

│   ├── models/              # Tag、Todo、TimeEntry、Summary 等数据模型
│   ├── handlers/            # HTTP API 参数解析、状态码和 JSON 响应
│   ├── store/               # 数据库 CRUD、任务树、时间记录冲突检查
│   ├── analysis/            # 每日/每周统计、趋势和对比计算
│   ├── server/              # 路由、CORS、静态资源和 SPA fallback
│   └── tutil/               # 时间格式、时区和日期工具
├── web/
│   ├── index.html           # 单页应用骨架和四个视图
│   ├── app.js               # 页面状态、渲染、交互和 API 调用
│   └── style.css            # 主题、响应式布局、时间轴和图表样式
├── bin/todo                 # 可选的本地启动脚本
├── Dockerfile               # Go 构建阶段 + scratch 运行阶段
└── docker-compose.yml       # 端口、时区和 ./data 持久化配置
```

## 个性化设置

- 白色 / 黑色主题，设置保存在浏览器本地。
- 时间轴可切换“全天”或“工作时段”。
- 工作时段的开始和结束时间可在设置页配置。

## 数据模型

| 数据 | 主要字段 | 说明 |
|---|---|---|
| 标签 `tags` | 名称、颜色、是否计入统计 | 分类与筛选基础 |
| 任务 `todos` | 标题、优先级、截止日期、父任务、完成时间 | 支持子任务层级，状态不再单独存储 |
| 任务标签 `todo_tags` | 任务 ID、标签 ID、`tag_order` | 多标签与主标签顺序 |
| 时间记录 `time_entries` | 任务 ID、标签 ID、开始/结束时间、备注 | 工作时间明细 |
| 每日总结 `daily_summaries` | 日期、`content` | 当日总结 |
| 每周总结 `weekly_summaries` | 周标识、`content` | 每周总结 |

## 快速开始

### 环境要求

- Go 1.22 或更高版本（本地运行和测试）。
- Docker Engine 及 Docker Compose（容器运行）。
- 不需要单独安装 SQLite，程序使用纯 Go 的 `modernc.org/sqlite` 驱动。

使用 Docker：

```bash
docker compose up -d --build
```

访问 `http://localhost:8080`。

本地运行：

```bash
go run .
```

运行测试：

```bash
go test ./...
```

## 配置

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `DB_PATH` | 容器 `/data/todo.db`；本地 `./data/todo.db` | SQLite 数据库路径 |
| `PORT` | `8080` | HTTP 服务端口 |
| `TZ` | `Asia/Shanghai` | 每日和每周统计使用的时区 |

数据保存在 SQLite 文件中。备份 `todo.db` 及可能存在的 `todo.db-wal`、`todo.db-shm` 文件即可。

## API

所有接口返回 JSON；请求体使用 `Content-Type: application/json`。日期使用 `YYYY-MM-DD`，时间记录使用 `YYYY-MM-DD HH:MM:SS`，周分析使用 ISO 周格式 `YYYY-Www`。

### 标签与任务

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/tags` | 获取全部标签 |
| `POST` | `/api/tags` | 创建标签；字段包括 `name`、`description`、`color`、`include_in_stats` |
| `PUT` | `/api/tags/{id}` | 更新标签 |
| `DELETE` | `/api/tags/{id}` | 删除标签及其任务关联 |
| `GET` | `/api/todos` | 获取任务树；可用 `tag_id`、`status_tag` 筛选 |
| `POST` | `/api/todos` | 创建任务；常用字段为 `title`、`description`、`priority`、`due_date`、`parent_id`、`tag_ids` |
| `PUT` | `/api/todos/{id}` | 更新任务及其标签 |
| `PATCH` | `/api/todos/{id}/status` | 兼容状态接口；`{"status":"done"}` 添加“已完成”标签，`pending` 移除 |
| `DELETE` | `/api/todos/{id}` | 删除任务及其子任务 |
| `GET` | `/api/todos/{id}/time-entries` | 获取任务及所有后代任务的时间记录 |
| `GET` | `/api/todos/{id}/time-entries/monthly?month=YYYY-MM` | 获取任务树在指定月份的时间记录 |

示例：

```bash
curl -X POST http://localhost:8080/api/todos \
  -H 'Content-Type: application/json' \
  -d '{"title":"整理项目文档","priority":1,"tag_ids":[1]}'
```

### 时间记录

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/time-entries?date=YYYY-MM-DD` | 获取指定日期的记录；省略日期时使用服务端当天 |
| `GET` | `/api/time-entries/active` | 获取当前进行中的记录，没有时返回 `null` |
| `POST` | `/api/time-entries/start` | 开始计时；请求字段为 `todo_id`、`tag_id`、`note` |
| `POST` | `/api/time-entries/stop` | 停止当前计时；没有活动记录时返回 `400` |
| `POST` | `/api/time-entries` | 手工创建记录 |
| `PUT` | `/api/time-entries/{id}` | 编辑记录 |
| `DELETE` | `/api/time-entries/{id}` | 删除记录 |

手工创建和编辑记录至少需要 `start_time`，`end_time` 可以为空表示进行中。正常情况下时间段重叠返回 `409`，响应中包含 `conflicts` 数组；确认需要重复统计时，在同一个请求体加入 `"allow_overlap": true` 后重试。

```json
{
  "todo_id": 3,
  "start_time": "2026-10-29 09:00:00",
  "end_time": "2026-10-29 10:30:00",
  "note": "编写项目说明"
}
```

### 分析与总结

| 方法 | 路径 | 用途 |
|---|---|---|
| `GET` | `/api/analysis/daily?date=YYYY-MM-DD` | 返回总工时、任务/标签占比、最长专注、小时分布和昨日对比 |
| `GET` | `/api/analysis/weekly?week=YYYY-Www` | 返回周趋势、最高产日、任务/标签占比、周时间记录和上周对比 |
| `GET` | `/api/summaries/daily?date=YYYY-MM-DD` | 获取当日总结 |
| `PUT` | `/api/summaries/daily?date=YYYY-MM-DD` | 使用 `{"content":"..."}` 保存当日总结 |
| `GET` | `/api/summaries/weekly?week=YYYY-Www` | 获取本周总结 |
| `PUT` | `/api/summaries/weekly?week=YYYY-Www` | 使用 `{"content":"..."}` 保存本周总结 |

未提供日期或周参数时，分析接口分别使用服务端当天或当前 ISO 周。

## 数据库与迁移

数据库默认使用 WAL 模式，并将最大连接数限制为 1，适合本地单实例使用。首次启动会自动创建父目录、执行 `internal/db/schema.sql` 并创建索引；不会要求手工执行迁移脚本。

当前 schema 的核心表为 `tags`、`todos`、`todo_tags`、`time_entries`、`daily_summaries` 和 `weekly_summaries`。启动时还兼容旧版本的 `groups`、任务 `status`、旧时间记录分组字段，并将它们迁移到标签模型。升级前建议先停止服务并备份整个 `data` 目录。

测试覆盖数据库初始化、标签/任务 CRUD、任务层级与状态标签、时间记录校验与重叠冲突、计时开始/停止、每日/每周分析和 HTTP API。前端没有独立构建步骤，HTML、CSS 和 JavaScript 会在 Go 编译时通过 `go:embed` 一起打包。

## 数据备份与注意事项

- 备份时复制整个 `data` 目录，而不是只复制 `todo.db`；SQLite WAL 模式下可能同时存在 `todo.db-wal` 和 `todo.db-shm`。
- 不要在多个进程或多个容器中同时写入同一个数据库目录。
- 允许重叠记录会导致总工时重复计算，适合记录并行工作但不适合常规录入。
- `TZ` 影响后端的“今天”、ISO 周和分析边界；部署后不要频繁修改，否则历史记录会按不同日期边界统计。
- 当前服务没有登录和权限系统，默认适合本机或受信任内网使用；暴露到公网前应增加反向代理认证和 HTTPS。
